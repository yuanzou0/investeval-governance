# InvestEval 120秒演示脚本

## 录制准备

- 使用桌面浏览器，窗口保持16:9；
- 打开 <https://investeval-governance.gao44y.chatgpt.site>；
- 使用新的浏览器存储环境，确保初始待复核数量为10；
- 关闭无关标签、通知和包含个人信息的窗口；
- 只展示合成数据，不打开开发者工具；
- 目标时长：约120秒，允许范围60至180秒。

## 分镜与旁白

### 0–12秒 产品定位

画面：质量工作台首屏。

> 这是InvestEval，一个投资Agent回答质量与个性化治理平台。它把匿名问答日志转化为可追溯的事实、KYC、合规和版本治理结论。当前演示使用合成冻结数据，不代表实时行情或投资建议。

### 12–30秒 双评测集与指标口径

画面：指向“32条配对样本62.5%基线”和“Bad Case压力集23.1%”。

> 平台把两种目的不同的数据分开。32条场景分层样本覆盖四类意图，Baseline通过率62.5%，但这是合成覆盖比例，不是线上准确率；13条压力样本中有10条异常，用于验证错误发现和复核链路。

### 30–50秒 答非所问和证据

操作：问题类型选择“答非所问”，点击 `relevance-partial-answer`，然后确认问题。

> 用户同时询问收盘价和涨跌幅，Baseline只回答收盘价，必需要点覆盖率只有50%。即使已回答的数字正确，仍被标记为答非所问；详情同时保存Prompt、数据版本和事实ID。

### 50–78秒 真实改善闭环

操作：打开“改善闭环”。

> 这不是手工填写的Candidate结果。同一问题先由Prompt v1产生50%覆盖的失败结果，人工复核归因为缺少覆盖合同；Prompt v2补齐两个要点后，评测器重新执行，覆盖率变为100%，两条事实都通过核验。输入哈希和JSON产物可以复现。

### 78–102秒 版本比较与上线门控

操作：打开“版本对比”。

> Candidate在同一批32条案例上的通过率从62.5%提升到90.6%。页面同时按行情、财务、公告和个性化分别报告，四类均未退化。但P95延迟840毫秒，超过800毫秒门槛，所以单例修复成功也不等于可以上线，决策仍是HOLD。

### 102–120秒 评审访问与总结

操作：打开“评审访问”。

> 完整代码包含30项自动测试、可复现JSON证据和AI使用记录。产品与仓库都是公开只读链接，评审无需登录或接受邀请。当前原型证明治理链路可运行，不声称已生产上线。

## 录制后检查

- 时长在60至180秒之间；
- 数字与 `artifacts/` 一致；
- 清楚说出“合成冻结数据”和“HOLD”；
- 没有出现API密钥、个人邮箱、浏览器历史或其他隐私信息；
- URL、文字和鼠标操作清晰可见；
- 音频没有长时间停顿或背景噪音。
